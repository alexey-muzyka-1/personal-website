# Бот личной воронки

Обычный текстовый Telegram-бот. Принимает deep link с меткой источника,
запоминает, из какого Reel пришёл человек, и отдаёт одну из статей сайта
через ссылку, по которой считается переход.

Не Mini App, не веб-чат, не каталог продуктов. Архитектура и границы —
`90 Личная воронка/00 Личная воронка.md` в vault, задачи — `04 Тикеты.md`.

## Что уже работает (тикет 01)

```text
/start <source_id>
  → users + attributions + событие bot_started
  → один рекомендованный материал + кнопка «Мне это не подходит»
  → выбор материала: событие material_selected и одноразовая ссылка /r/<токен>
  → переход по ссылке: событие material_opened, редирект на статью
```

Чего здесь намеренно нет: анализа Reel, урока, оплаты, обязательной
подписки на канал, меню продуктов. Это следующие тикеты, и обещать их
раньше времени нельзя.

## Канал

Бот админ канала — значит считает и его: кто подписался, кто ушёл, кто из
пришедших в бота дошёл до подписки.

```text
chat_member от Telegram → channel_members + channel_events
getChatMemberCount раз в 30 минут → channel_size
getChatMember по всем известным людям раз в 6 часов → сверка
```

Границу задаёт Bot API, и она жёсткая: **списка подписчиков не
существует**. Есть общее число, статус конкретного известного нам
человека и события про входы и выходы с того момента, как бот стал
админом. Поэтому у людей из старой базы даты подписки нет и не будет:
она не подставляется «сегодняшним числом», а остаётся пустой, и в отчёте
стоит отдельной строкой. Иначе первая же сверка нарисовала бы прирост на
всю накопленную базу за один день.

Отсюда же три когорты на странице «Канал»: подписались после бота (это и
есть работа воронки), были подписаны раньше, подписались неизвестно
когда. Складывать их в одну цифру «конверсия в подписку» нельзя.

Канал предлагается в двух местах: после записи на эфир и вместо любого
отклонённого оффера. Второе важнее: «мне это не подходит» раньше вело к
уточняющему вопросу, а тот — обратно к тому же предложению. Это был не
выход, а круг.

## Блокировка

`my_chat_member` из личного чата означает, что человеку больше нельзя
написать ничего. Тот же тип update из канала означает совсем другое —
что бота сняли с админов, — поэтому обработчик развилкой по типу чата
разводит их в разные стороны.

Без этой отметки предзапись на десять человек тихо превращается в
рассылку на семь, и выясняется это в день эфира. В карточке человека и в
выгрузке блокировка стоит рядом с «написать»: ссылка на переписку
работает, а сообщение не дойдёт.

Заблокировать бота можно и не запуская его — из профиля. Такому человеку
карточка не заводится: в базе лидов он не лид, и строка в `users`
испортила бы знаменатель во всех отчётах.

## Устройство

| Пакет | Роль |
|---|---|
| `internal/funnel` | сценарий и тексты. Не знает про Telegram и про базу |
| `internal/channel` | замер канала: подписки, отписки, размер, сверка |
| `internal/telegram` | webhook, разбор update, вызовы Bot API |
| `internal/store` | Postgres: база лидов |
| `internal/memstore` | то же в памяти — для тестов и прогона сценария |
| `internal/admin` | JSON для админки и раздача её страниц |
| `admin-ui` | сам интерфейс админки на Astro, собирается в статику |
| `cmd/bot` | конфигурация из окружения, HTTP-сервер, graceful shutdown |

Один update = одна транзакция. Отметка «этот update обработан» пишется
вместе с событиями, поэтому сбой базы не съедает лида: Telegram повторит
доставку, и шаг пройдёт заново.

## Переменные окружения

| Имя | Обязательна | Что это |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен из BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | да | случайная строка; Telegram шлёт её в заголовке, чужие запросы отсекаются |
| `DATABASE_URL` | да | DSN Postgres |
| `PUBLIC_BASE_URL` | да | публичный адрес бота, например `https://bot.alexeymuzyka.com` |
| `SITE_BASE_URL` | нет | адрес сайта, по умолчанию `https://alexeymuzyka.com` |
| `ADDR` | нет | адрес прослушивания, по умолчанию `:8080` |
| `TELEGRAM_CHANNEL_URL` | нет | канал, по умолчанию `https://t.me/alexeymuzykablog` |
| `TELEGRAM_CHANNEL_ID` | нет | канал числом: нужен только приватному каналу без публичного имени |
| `ADMIN_HIDDEN_TELEGRAM_IDS` | нет | свои тестовые аккаунты через запятую: не попадают ни в одну цифру на `/admin` |

Webhook регистрируется сам, на каждом старте. Флага для этого нет
намеренно: набор типов update меняется вместе с кодом, Telegram заменяет
прежний набор целиком, и «выкатить и не забыть один раз включить
переменную» — это способ остаться без половины событий. Накопившаяся
очередь при этом не сбрасывается: за время простоя в ней люди.

Секреты живут только в окружении хостинга. В репозитории их нет и быть
не должно.

## Запуск

```bash
# миграции — отдельным шагом, руками
migrate -path migrations -database "$DATABASE_URL" up

go test ./...
go run ./cmd/bot
```

Запросы страницы `/admin` проверяются на настоящем Postgres: ломается там
не логика на Go, а SQL — порядок колонок, пустая строка вместо `NULL`,
`group by`, съедающий строки. Без `TEST_DATABASE_URL` эти тесты
пропускаются, поэтому обычный `go test ./...` базы не требует.

```bash
docker run -d --name funnel-test-pg -e POSTGRES_PASSWORD=test \
  -e POSTGRES_DB=funnel -p 55432:5432 postgres:17-alpine

TEST_DATABASE_URL='postgres://postgres:test@localhost:55432/funnel' \
  go test ./internal/store/
```

Тест сам накатывает миграции из `migrations/` и пересоздаёт схему перед
каждым случаем, так что базу можно не чистить руками.

## Админка

Страницы живут в `admin-ui` (Astro) и собираются в статику, которую Go
вшивает в бинарник через `go:embed`. Данные они забирают с `/admin/api`.

Почему так, а не отдельным сервисом: Node в проде — это второй контейнер,
второй рантайм и второй способ уронить машину, а если бы он ходил в базу
сам, схему базы лидов знали бы двое. Здесь схему знает только Go, а
вёрстка правится и пересобирается без него.

```bash
cd admin-ui
npm ci
npm run build      # кладёт файлы в internal/admin/ui, откуда их берёт go:embed
```

Сборка не коммитится. В проде это делает Docker отдельным слоем перед
сборкой Go. Если интерфейс не собран, бот всё равно работает: `/admin`
покажет страницу с этой командой, а в лог уйдёт `admin ui is not built` —
webhook важнее админки и падать из-за неё не должен.

## Эндпоинты

| Путь | Зачем |
|---|---|
| `POST /telegram/webhook` | приём update, только с верным секретом |
| `GET /r/{token}` | переход на статью со счётчиком |
| `GET /admin/` | админка: обзор, источники, канал, сообщения, люди |
| `GET /admin/api/*` | данные для неё: overview, sources, channel, scenario, people, person |
| `GET /admin/export.xlsx` | тот же срез книгой Excel: листы «Люди», «Шаги» и «Канал» |
| `GET /healthz` | проверка живости для хостинга |

## Что нужно, чтобы включить это по-настоящему

1. Бот и токен в BotFather.
2. База Postgres и прогнанные миграции.
3. Хостинг с постоянным процессом и HTTPS-доменом.
4. Бот — админ канала. Без этого Telegram не отвечает про канал ничего:
   ни размера, ни статуса человека, ни событий. На странице «Канал» это
   видно сразу — снимок перестаёт обновляться.
5. Сквозная проверка на тестовом пользователе — только после неё можно
   закрывать верхний чекбокс тикета 01.

## Карта бота

`BOTMAP.md` — все входы, реплики, кнопки, события и крайние случаи на
одной странице. Она не пишется руками: `go run ./cmd/botmap > BOTMAP.md`
прогоняет настоящий сценарий и записывает то, что бот реально отвечает.
Тест `TestBotMapIsUpToDate` падает, если карта разошлась с кодом.
